entirely, so the constraint cannot bite at all.

REBUILD REQUIRED when the data plane URL changes:
  cd dashboard-web
  NEXT_PUBLIC_DATA_PLANE_URL=<https origin> npm run build
  cd out && zip -qr /tmp/dash.zip . && cd ..
  # then create-deployment / PUT the zip / start-deployment

NEXT_PUBLIC_* is inlined at BUILD time, so changing the origin needs a
rebuild, not just a redeploy.

RESOLVED - the data plane origin is HTTPS via CloudFront.
An https Amplify page cannot fetch the http-only ALB; the browser blocks it as
mixed content. The stack's own CloudFront distribution is the https front door
and the ALB actively refuses direct access.

SSE through CloudFront was the open risk and it is CLEAR: measured first byte
at 0.06s with update frames arriving continuously, not buffered. The
distribution's TTLs are already 0, so no cache policy change was needed.
