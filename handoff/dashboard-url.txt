STATUS: LIVE. Verified HTTP 200 and serving the branded dashboard.

Hosting: AWS Amplify Hosting, app "awsday-gateway-dashboard", branch "main",
region eu-central-1. Deployed by MANUAL (zip) deployment, not a GitHub
connection - connecting Amplify to GitHub needs an OAuth grant, and a manual
deployment needs nothing but credentials.

The app is a FULLY STATIC Next.js export (output: "export"). That is better
than it sounds: dashboard-brief.md section 2 works around Amplify not
supporting Next.js streaming by keeping the live path off the compute
provider. A static export removes the compute provider from the picture
entirely, so the constraint cannot bite at all.

REBUILD REQUIRED when the data plane URL changes:
  cd dashboard-web
  NEXT_PUBLIC_DATA_PLANE_URL=<https origin> npm run build
  cd out && zip -qr /tmp/dash.zip . && cd ..
  # then create-deployment / PUT the zip / start-deployment

NEXT_PUBLIC_* is inlined at BUILD time, so changing the origin needs a
rebuild, not just a redeploy.

OPEN ITEM - the data plane origin must be HTTPS.
An https Amplify page cannot fetch an http origin; the browser blocks it as
mixed content. The upstream ALB is http-only, so the data plane has to be
reached through the stack's CloudFront distribution (https) rather than the
ALB directly. Note that CloudFront must be configured with caching DISABLED
on the SSE path or it will buffer the stream.
